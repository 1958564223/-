v4.39 最新版本
新增
  • 「宠物屋」上线了 —— 聊天界面右下角会有一只可以拖着走的小宠物，点它有菜单，能进它的小窝。里面可以领养、喂食、陪玩、摸摸，看它一点点长大。
  • 小窝里的宠物不是贴图，是活的：饿了会冒气泡催你，饱了会顶到上限不让你再喂，成长值和相处天数一起决定它什么时候长大。
  • 多了一种新成员：鹦鹉。它从蛋里出来，破壳的时候才定下品种（金太阳、太阳锥尾、牡丹、虎皮、金刚、青金刚、吸蜜、白化玄凤 —— 全是艳色的）；花纹看你们怎么相处，越亲越好看；养大了能羽化成神兽（朱雀 / 青鸾 / 雪羽鹓鶵 / 金辉鸾凤），羽化之后血脉不变，还是原来那只。
  • 它会提醒你去给它画一张专属模样：破壳、长大、羽化都会当场喊你一声，小窝顶部有提示条，宠物头顶冒一个金色的点，点一下就能给它画。但生图不会自动触发 —— 那是要花钱的，只有你自己点了才会画。
  • 聊天里的角色也知道它存在：它会主动提你的宠物、主动想喂它，而且性格跟你在别处聊的是同一个。
移除
  • 「邮箱」整个下线了 —— 界面、写信那段逻辑、备份导出、图标槽位全删干净了，你的数据库里那个邮箱表也真的删掉了（不是只藏起来）。顺手把邮箱留下的样式也清了 481 行。
  • 老备份里如果还有邮箱字段，导入时会被自动跳过，不会报错。
修复
  • 桌宠之前点不动 —— 你的原话是「点蛋弹出的隐藏和进小屋都没用」「难道电脑点击不行要触摸」。真因不是要触摸：浏览器按下时会自动把指针锁在按下元素上，而代码没认出「按的是菜单里的按钮」，于是 click 被抢走，按钮的回调压根没跑。鼠标和触摸都不行，现在都修好了。
  • 还有「进去没有桌宠」 —— 桌宠的显示逻辑装得太晚，你点进聊天页的时候它还没准备好。现在进聊天页一秒内就出来，还会盯着当前在哪个界面自动收起。
  • 桌宠被弹窗挡住的时候会自己让位藏起来，关掉弹窗自己回来 —— 不会再出现「看着在那儿、点却没反应」的情况。

  • 影院聊天换成「外面主聊天的那套」了 —— 以前陪你看剧是 Gemini Live 一个模型同时干两件事：既要看视频画面，又要回话。用户原话：「又要看视频又要回话实在太蠢了，性格也和外面聊天的不适配」。

  • 按你点的清单，影院上下文里装的是：人设 ✅ 长期记忆 ✅ 外面聊天框的正常上文 ✅ 影院攒下的全部剧情记忆（摘要 + 单集剧情）✅ 世界书 ❌（你说不要，就没带）。
  • 另外主聊天那套提示词里有一大段「输出 JSON 数组」的指令（发表情、发图片、转账那些），影院里一条也执行不了，所以整段剥掉了 —— 现在影院里它回的是普通聊天文字，跟你在外面聊天看到的一模一样。

  • 影院里说的话会记进主聊天历史 —— 你的原话是「影院的会话就是要主聊天知道啊，不存在污染」。所以在影院聊的，出门接着聊能接上茬；看完导出的剧情记忆也会进长期记忆。
  • 顺手补了一点：Live 没连上也不挡聊天了 —— 以前「Gemini 还没就绪」会直接不让你在影院说话，现在陪聊不依赖 Live，只有「看不到此刻画面」这一项受影响。

v4.35 2026-10-23
修复
  • 换 API 预设之后，其它功能还在用旧地址 —— 悬浮球里换一个站点预设，主聊天立刻就换过去了，但专注计时、角色生成、表情包识图、情侣空间日记这些还在用换之前的地址，最坑的是会变成「旧地址 + 新模型」的错配。
  • 真凶：站点预设模式下，数据库里只存「用了哪个预设」，不再存地址和密钥。程序启动时会读一次预设、把地址填回内存里，所以平时看着都好好的 —— 但那是启动时拍的那张快照。换了预设以后只有「引用」变了，快照还是旧的，几十处读它的功能就全在用旧地址。
  • 修法：换预设 / 改预设之后，立刻把地址刷新一遍。设置页换槽位预设、悬浮球换主 API 预设、保存 API 设置、预设库里改了或删了预设 —— 五个入口全接上了。以后换完预设，所有功能立刻一起换过去。
  • 另外有几处本来就一直是坏的，这次一并修了（它们读的是数据库里那一行，而那一行在预设模式下本来就是空的）：角色生成（预设模式下必然弹「请先配置 API」）、专注计时、绿水续写 / 作者追更（弹「API配置不完整」）、表情包识图（识图专用 API 配了预设的话，它会误以为你没配、偷偷回退到主 API）。
  • 情侣空间那一整套（日记、相册、树、清单、时光轴、信件…… 一共 41 处调用）也改成实时读「情侣空间专用 API」，配了专用站点的现在会真的用上。
  • 顺手还修了两处小毛病：专注计时那个地址无条件多拼了一次 /v1（你的站点地址本来就带 /v1，再补一次就变成 /v1/v1/…，网关直接回 404，就是前几天记忆总结那个毛病）—— 现在跟主聊天一个写法，只补 /chat/completions；悬浮球「保存当前配置为预设」以前会存下一个空预设（预设模式下地址是空的），现在存的是真正在用的那套。

修复
  • 「今日私选」会让 AI 掉链子的三个地方，这次一起修了 —— 上一版只是让「AI 没接上」这件事看得见，但那三个地方本身还在。这版是让它们少发生。
  • ① 地址明明读到了，程序却自己把它扔了 —— 以前是「预设读成功、但模型名那一栏是空的」就把整份配置丢掉，回落到那个本来就空的输入框，等于白读一次。现在改成：地址和密钥有效就用，模型名单独去别处兜，不会再自己把已经拿到手的东西丢掉。
  • ② 30 秒超时，对手机和免费额度来说太紧了 —— 以前一次要问 AI 100 首候选、再让它写出 20 首带理由的话，光「读」就要十几秒，「写」又要二三十秒，必定超。现在候选砍到 60 首（挑 20 首绰绰有余）、超时放宽到 45 秒，整轮的总预算也从 90 秒放宽到 150 秒。
  • 整轮预算这条特别关键：以前最坏情况会顶到总预算 → 整轮直接报错、一张卡都没有，那比「退而求其次出一张卡」糟得多。现在剩下的时间不够再问一次 AI 时就不问了，直接出兜底卡，保证你总能拿到卡。
  • ③ AI 给的歌曲对不上，整轮就白跑了 —— 以前歌曲 id 有一个对不上就被丢掉，对不上就等于没策展成。现在改成三层匹配：id 对得上就用；id 没对得上就按歌名去认（AI 抄错 id 是常事，歌名对得上照样算它选对了）；两样都对不上才丢 —— 放宽归放宽，白名单外编出来的歌还是进不来。
  • 顺带认得下 AI 各种奇怪写法：字段叫 songId / song_id 也认，id 写成「186016.0」或者前后带空格也认。
  • 以后再出问题，猜都不用猜了 —— 这张卡里会记一份对账表（AI 给了几条、认上几条、靠歌名救回几条、丢了几条），卡片上写「这次 AI 没接上」的时候，原因和细节都在里面。

  • 视频通话结束后，通话记录里看不见你自己说的话 —— 用户那几条显示成 [object Object],[object Object]，AI 那几条却好好的，语音通话也完全正常。

修复
  • 「今日私选」每首歌的推荐理由都一模一样 —— 整张卡的理由全是「来自 XX，跟你最近在听的是同一个方向。」，看着像批量生成的，一点推荐味都没有。

  • 修法：改成跟主聊天一样去读 API 预设，AI 现在真的会被叫起来，每首歌的理由是它按你的口味现写的；兜底那几句也改成轮换说法，万一哪天 AI 真挂了，卡片也不会再像复制粘贴；另外加了一道检查，模型要是偷懒把十几首写成同一句理由，会被换掉。

  • 新增通话诊断 (为排查挂断闪退) — 把挂断流程拆成若干步 (刚点挂断 / 释放画布后 / 关摄像头麦克风后 / 记录写库后 / 聊天写库后 / 切回界面后 / 全部完成), 每推进一步就落一次盘。万一崩在挂断途中, 下次打开时那个「崩溃恢复」提示会直接告诉你卡在哪一步, 而不是只知道"闪退了"。顺带记录是否发生过 WebGL 显存耗尽。iPhone PWA 装到主屏后没有 console, 这是唯一的复盘入口。只记数字和阶段名, 不含聊天内容。
优化
  • 「Gemini 剧情记忆」从聊天框里拆成独立页面 — user 原话"那个Gemini剧情记忆弄在聊天对话框上, 又要显示剧情, 又要显示聊天记录, 想改点剧情总结, 键盘一弹看都不怎么看的见, 能不能上方设置那一排单独弄个按钮Gemini剧情记忆, 把这个剧情记忆单独拆个页面出来, 不要和观剧聊天吐槽框混在一起"。原来它是聊天面板顶部的一条折叠条(收起一行标题, 展开吃 45% 高度、聊天记录自动让位), 手机屏上两边互相挤, 一弹键盘正文基本看不见。现在: 顶栏加「记忆」按钮(紧挨设置, title 写全「Gemini 剧情记忆」)→ 底部上滑的独立页, 跟设置/片单同一套手感, 打开时自动收起聊天面板; 页面自带的「关闭」按钮退出。折叠条那套(点标题展开/收起、点空白处折叠)整个删掉, 进来永远是展开的完整正文。按钮标签用两字跟其他按钮齐平(停止/设置/聊天/片单/退出 都是两字), 四字会把这一行挤到换行。
修复
  • 修复换短剧会把上一部剧的记忆混进新剧的前情提要 — 退出总结失败会存草稿, 下次进影院自动恢复, 而恢复之后如果用户选的是【另一部剧】, setSeries 只换了剧名却没清上一部剧攒下的单集记忆和总纲, 于是新剧攒记忆时混进旧剧剧情, 退出时那份被污染的提要会【永久写进新剧的那一行】。前情提要是按剧存的, 污染一旦写进去就固定下来了, 比以前更难察觉。修法: setSeries 里按 seriesKey 是否真的变了来判换剧 (⚠️ 每播一集都会调一次 setSeries, 按"调了没调"清会把连播的第一集记忆清空), 清之前先 saveDraft() 保住旧剧记忆, 不让那几集白看。
  • 修复前情提要的正文可能混进长期记忆 — 一次调用出两份后如果把整段直接存进长期记忆, 用户下次聊天会读到一整段剧情提要, 跟生活记忆混在一起。改为按【前情提要】标记拆开; 拆不出来(格式跑偏)就整段当观影记忆, 行为退回本次改动前, 绝不因为格式跑偏而丢掉真正的观影记忆。
  • 修复短剧前情提要【只有第一次会生成, 之后就再也不更新】(user 实测: "第一次总结了前情提要…后面再怎么进进出出的看, 前情提要都不再总结了, 我都看到60集了还在44")。症状是观影记忆照常存、前情提要永远停在第一次那版, 且界面完全看不出哪里坏了 —— 因为写前情提要的函数在收到空内容时【第一行就返回】, 一条都没写, 也没任何提示。真凶: 第一版拆解只认死字符串 `【前情提要】` 且假定它一定在观影记忆后面。首次退出时指令里没有旧提要, 模型老实按格式输出所以正常; 从第二次起旧提要进了指令, 模型排版就变了(可能写成 `**前情提要**`、`前情提要：`, 也可能把两段写反), 拆解一律失败。修法分三层: ①拆解认得几种标题写法, 两段写反也能拆, 且标题必须独占一行才算(免得记忆正文里随口一句"我们上次说的前情提要…"被当成标题、把观影记忆拦腰砍断); ②拆分失败时补一次【只写前情提要】的专门调用(主路还是"一次调用出两份", 只在主路没产出时才多花一次, 宁可多花一次也不能让功能静悄悄停摆); ③失败时补了日志, 下次再犯控制台会直接写明原因。
  • 修复 Gemini Live【连了断了连, 最后彻底连不上】+【看完一集没总结起, 重看一遍还是没有】(user 实测: "整死连不上模型, 连了断断了连…以前也有这个现象, 回看过去的剧集就连不上")。三个缺陷叠在一起: ①重连的"成功"判断是假的 —— `live-client.js` 的 `connect()` 在 socket `onopen` 就 resolve, 而且 resolve 的是【客户端实例】不是布尔值; 而 `cinema-live.js` 写的是 `reconnect().then(ok => { if (ok) 报成功 })`, `ok` 永远为真 → 每次重连都报"✅ 重连成功, 上下文已恢复"并重启帧循环, 哪怕 setupComplete 根本没来、服务端下一秒就关掉了。外面看日志全绿, 实际是死连接。改为必须等 `isReady()` 真为真才算成功, 等不到就按失败继续退避重试。②链子只修了一半 —— 那个 `.then` 没有 else 分支; 而且 `enable()` 发现旧存档点续不上时会清掉 handle 然后 `resolve(false)`, 但调用方 `autoConnect` 根本不看返回值, 于是"把废 handle 清干净"做完了却【没有任何人再发起下一次连接】。现在两个失败分支都会主动排重连。③断线时在途的摘要请求没人管, 会赖到它自己 45s 超时: 期间 `requestEpisodeSummary` 第一行就 return → 后面每一集都不再总结(user 原话"重看一遍还是没有"); 更糟的是 `handleModelText` 会把模型吐的每一个字都收进那个僵尸 buffer, 一个字都不进气泡 → 看着像"连上了但不理我"。现在断线这一刻就立刻作废它。附带修了一处隐蔽的: 清存档点时只删了 localStorage, 客户端对象里的 `_resumeHandle` 还留着, 下次重连照样拿同一个废 handle 去续 —— 现在两处一起清。
  • 修复通话挂断瞬间闪退 + 两处资源泄漏 — 挂断流程整个重排: 摄像头/麦克风/AudioContext/WebGL 的释放【提前到两次落库 await 之前】(原来整个落库期间它们还活着, 而那正是闪退要顶的峰值窗口); 挂断时清空通话气泡 DOM (切屏只是切 class, 那些气泡原本要等下次开会话才清, 挂断那刻又撞上聊天记录全量重渲染, 两边同时活在 DOM 里); 切回聊天界面改成 await, 不再和 AI 主动回话一起 fire-and-forget 叠在同一帧; 通话记忆总结挪到界面稳定之后再跑 (产物写长期记忆, 晚几百毫秒无差别)。两处泄漏: ①通话舞台每换一次背景都 createObjectURL 却从不 revoke (换 N 次漏 N-1 张, 每张一两 MB), 改为挂上新图后再释放上一张 (顺序不能反, 反了背景闪白); ②Live2D 挂载途中挂断 → 刚建出来的 PIXI/WebGL/纹理永远没人回收 (canvas 已脱离 DOM 找不回来), 现在挂载完成时自检 isConnected, 已挂断就当场销毁。另外顺手去掉挂断后那条"请主动发一两句"的隐藏系统指令 + 主动回话 —— 最后一句必然是 AI 说的, 再补一句没必要, 还会留一条幽灵系统消息在历史里等下次被误触发。
