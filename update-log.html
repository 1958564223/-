关于更新日志

之前有人建议我把330的更新日志做个日志放上去，问题是我的更新日志文件因为换电脑不慎丢失了，所以更新日志从本次（明天）更新后开始记录。

v4.19 最新版本
新增
  • 短剧「前情提要」— 之前短剧的单集剧情记忆和总纲全都只在内存里, 退出精炼成功后一律清空, 所以下次进影院时模型对这部剧是【零认知】(user 原话"我有时候时间比较零碎, 看个四集就会退出去…下次再进去看的时候, 观影模型就没了这个剧的前情提要, 然后他总结中间剧情的时候就会有点懵逼")。而且这不是只有下次有问题 —— 审计时发现总纲从来只喂给"20 集合并"和"退出精炼"两个后台任务, 整场观影期间模型压根没拿到过它。现在每部剧在 Dexie v68 新表 cinemaSeriesRecap 里存一份跨场底稿: 退出时跟观影记忆【同一次调用】一起生成 (客观剧情提要, 开头带【已看到第 N 集】, 限 1800 字), 进片时作为一个静默后台回合喂回模型 —— 走 sendUserText 这条通道, 绝不塞进系统提示词 (v4.13 刚因为往那儿塞长期记忆治好了"接话降智/雷霆语言")。剧情记忆面板里能看到这份提要, 也能手动删除 (user 明确要"最终由用户手动删除")。
修复
  • 修复换短剧会把上一部剧的记忆混进新剧的前情提要 — 退出总结失败会存草稿, 下次进影院自动恢复, 而恢复之后如果用户选的是【另一部剧】, setSeries 只换了剧名却没清上一部剧攒下的单集记忆和总纲, 于是新剧攒记忆时混进旧剧剧情, 退出时那份被污染的提要会【永久写进新剧的那一行】。前情提要是按剧存的, 污染一旦写进去就固定下来了, 比以前更难察觉。修法: setSeries 里按 seriesKey 是否真的变了来判换剧 (⚠️ 每播一集都会调一次 setSeries, 按"调了没调"清会把连播的第一集记忆清空), 清之前先 saveDraft() 保住旧剧记忆, 不让那几集白看。
  • 修复前情提要的正文可能混进长期记忆 — 一次调用出两份后如果把整段直接存进长期记忆, 用户下次聊天会读到一整段剧情提要, 跟生活记忆混在一起。改为按【前情提要】标记拆开; 拆不出来(格式跑偏)就整段当观影记忆, 行为退回本次改动前, 绝不因为格式跑偏而丢掉真正的观影记忆。

v4.15
修复
  • 修复变量记忆玄关"清空回收站 / 删除选中"点了提示已清空但卡片还在的真因 — class 里有两个同名 `deleteFragments` 方法（旧版接收 string id array，新版 async 接收 fragment object array），JS class 后定义覆盖前定义，新版覆盖了旧版，但 handler 还在传 string id array，导致新版内部 `fragments.map(f => f.id)` 把 string 当对象取 .id 全部变 undefined，Set 装 undefined → filter 不删任何东西 → toast 弹"已清空 N 条"（handler 用 ids.length 自算，不是返回值）但实际没删。单条删除 OK 因为用的是 `deleteFragment`（单数）没重名。修法：把 `deleteFragments(chat, fragments)` 改成兼容两种传法（`typeof item === 'string' ? item : item.id`），3 个传 string array 调用方 + 1 个传 fragment array 调用方都能正常 work。
